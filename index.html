01About me

I build the part of the product people actually touch.

I'm Monika — a Flutter developer from Tiruchirappalli who has spent the last two-plus years turning designs, APIs and half-formed ideas into apps that run on real phones.

Most of my days are spent in Flutter and Dart: wiring up REST APIs, setting up Firebase, shaping state with Provider and making sure a screen still looks right on the smallest Android device in the room. I like work that sits between design and engineering — the spacing has to feel right, but so does what happens underneath: how data flows from an API into a model, where state should live, and whether the next developer can understand a widget without scrolling through six hundred lines.

Lately a lot of my curiosity goes into AR, VR and 3D — placing GLB models in the real world, experimenting with Unity alongside Flutter, and figuring out what immersive features look like inside an everyday mobile app. I'm also steadily improving how I structure applications, because clean architecture is what keeps a codebase pleasant as it grows.

Before Flutter, I worked in data processing and documentation. It taught me patience with detail — which turns out to be very useful when you're tracing why one field in an API response is null.

08How I write Flutter

Clean layers.
Calm widgets.

Most bugs I've fixed came from things being in the wrong place — network calls inside widgets, state that nobody owns, screens that forget about errors. So I keep the layers simple:

  • repository talks to the API and returns typed models.
  • provider owns the state and decides what the screen should show.
  • widget just renders — loading, empty, error or data.

// illustrative example, written for this page

class PropertyRepository {
  PropertyRepository(this._api);
  final ApiClient _api;

  // One place that knows the endpoint and the JSON shape.
  Future<List<Property>> fetch({PropertyFilter? filter}) async {
    final res = await _api.get('/properties', query: filter?.toQuery());
    return (res['data'] as List)
        .map((json) => Property.fromJson(json))
        .toList();
  }
}
enum ViewState { idle, loading, ready, empty, error }

class PropertyProvider extends ChangeNotifier {
  PropertyProvider(this._repo);
  final PropertyRepository _repo;

  List<Property> items = [];
  ViewState state = ViewState.idle;
  String? error;

  Future<void> load({PropertyFilter? filter}) async {
    state = ViewState.loading;
    notifyListeners();
    try {
      items = await _repo.fetch(filter: filter);
      state = items.isEmpty ? ViewState.empty : ViewState.ready;
    } on ApiException catch (e) {
      error = e.message;
      state = ViewState.error;
    }
    notifyListeners();
  }
}
class PropertyList extends StatelessWidget {
  const PropertyList({super.key});

  @override
  Widget build(BuildContext context) {
    final provider = context.watch<PropertyProvider>();

    // Every state gets a screen — not just the happy path.
    return switch (provider.state) {
      ViewState.loading => const ListSkeleton(),
      ViewState.empty => const EmptyState('No properties found'),
      ViewState.error => ErrorState(onRetry: provider.load),
      _ => ListView.separated(
          itemCount: provider.items.length,
          separatorBuilder: (_, __) => const SizedBox(height: 12),
          itemBuilder: (_, i) => PropertyCard(provider.items[i]),
        ),
    };
  }
}

09Quick answers

Things people usually ask.

What kind of apps do you build?

Cross-platform Flutter apps for Android and iOS — marketplaces, field-operations tools, team and business apps, and immersive AR/VR experiences like Trauell.

Can you work on an existing Flutter codebase?

Yes. A good part of my work has been adding features to apps that were already in production — reading the existing code first, following its patterns, and improving things carefully rather than rewriting them.

Do you handle the backend as well?

My focus is the app, but I'm comfortable on the Firebase side — Authentication, Firestore, Cloud Functions, push notifications and Remote Config — and I work closely with backend developers on REST APIs, testing endpoints in Postman before they hit the UI.

Which state management do you use?

Mainly Provider, with GoRouter for navigation and deep links. I care more about state being predictable and living in the right place than about which package is currently popular.

What are you learning right now?

AR/VR and 3D (GLB models and Unity with Flutter), on-device ML Kit, Tamil speech-to-text, and getting better at app architecture and performance profiling with DevTools.
